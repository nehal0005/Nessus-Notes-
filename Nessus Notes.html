BASIC

1. What is Nessus?

Nessus is a vulnerability scanner made by Tenable. Think of it like a health check-up for computers and networks. It looks for weak spots (vulnerabilities) that hackers could use.

Simple example

Your house has doors and windows. A scanner walks around and checks: "Is this window unlocked? Is this lock old?" Nessus does the same for servers, laptops, routers, and websites.

Key words to know

  • Vulnerability: a weakness in software, settings, or hardware.
  • Exploit: a method that uses a vulnerability to attack.
  • CVE: a public ID for a known vulnerability (like CVE-2021-44228 for Log4Shell).
  • Patch: a fix from the vendor.
  • Target / Host: the device being scanned.
  • Plugin: a small check (script) Nessus runs. Nessus has 100,000+ of them.
💡 Nessus finds problems. It does not fix them and it is not a hacking tool by itself.
BASIC

2. How does Nessus work?

  1. Discovery: finds which devices are alive (ping, port checks).
  2. Port scanning: checks which doors (ports) are open, like 22 (SSH), 80 (HTTP), 443 (HTTPS), 445 (SMB), 3389 (RDP).
  3. Service detection: finds what software runs on each port and its version.
  4. Plugin checks: compares what it found with its database of known problems.
  5. Report: lists issues with severity, explanation, and fix advice.
Plugins update often, so always update them before scanning.

4. Install and run your first scan

  1. Download Nessus from the Tenable website and get a free activation code (Essentials).
  2. Install it (Windows, Linux, or macOS).
  3. Open the browser: https://localhost:8834 (the default port is 8834).
  4. Accept the certificate warning (it is a self-signed certificate, normal for local use).
  5. Enter the activation code, create a username and password. Nessus downloads plugins (takes some time).
  6. Click New Scan → choose a template → give a name and target (IP or range like 192.168.1.0/24) → Save → Launch.
⚠️ Only scan systems you own or have written permission to scan. Scanning others without permission is illegal. For practice, use your own lab (VirtualBox, Metasploitable, DVWA).

6. Severity and CVSS

Each finding gets a severity based on CVSS (Common Vulnerability Scoring System, score 0 to 10).

LevelCVSS scoreMeaning
Critical9.0 – 10.0Fix immediately. Easy to attack, big damage.
High7.0 – 8.9Fix soon.
Medium4.0 – 6.9Plan a fix.
Low0.1 – 3.9Minor risk.
Info0Just information (open ports, OS found).

Nessus also shows VPR (Vulnerability Priority Rating), a Tenable score that says how likely a bug is to be actually attacked soon. It helps you choose what to fix first.

INTERMEDIATE

7. Reading and using reports

Each finding shows:

  • Name and Plugin ID
  • Description (what the problem is)
  • Solution (how to fix)
  • See also (reference links)
  • CVE / CVSS / VPR
  • Plugin Output (proof: what Nessus saw)

Export formats

PDF, HTML, CSV (for Excel), and .nessus (XML, can be imported into other tools).

Simple steps after a scan

  1. Sort by severity. Start with Critical and High.
  2. Check for false positives (Nessus says "vulnerable" but it is not). Verify manually.
  3. Fix: patch, change settings, close unneeded ports.
  4. Re-scan to confirm it is fixed.
ADVANCED

8. Advanced topics

a) Custom policies and scan tuning

  • Create a Policy once and reuse it for many scans.
  • Enable or disable plugin families (e.g., turn off DoS plugins on fragile systems).
  • Tune speed: max simultaneous checks per host, and hosts at a time. Too fast can crash old devices or slow the network.
  • Choose port range: common ports, all 65535 ports, or custom.
  • Turn on "Safe checks" to avoid risky tests in production.

b) Compliance and configuration audits

Nessus can check if a system follows a standard, like CIS Benchmarks, PCI-DSS, HIPAA, or DISA STIG, using .audit files. Example: "Is password length at least 14? Is guest account disabled?"

c) Nessus Agents

Small software installed on laptops and servers. They scan locally and report back. Great for remote or roaming laptops, devices behind firewalls, and places where you cannot give credentials.

d) Scanners, scheduling and automation

  • Schedule scans daily, weekly, or monthly.
  • Email results automatically.
  • Use the REST API (with API keys) to launch scans and download reports through scripts (Python is common).
  • Scanner placement: put scanners inside each network segment to avoid firewall blocking.

e) Plugin writing (NASL)

Plugins are written in NASL (Nessus Attack Scripting Language). Advanced users write custom checks for their own software.

f) Integrations

Nessus data can feed SIEM tools (Splunk), ticket systems (Jira, ServiceNow), and exploit frameworks (Metasploit can import .nessus files to test findings).

g) Limits to know

  • It finds known issues only. It cannot find brand-new (zero-day) bugs or logic flaws.
  • False positives and false negatives happen.
  • It is a scanner, not a full penetration test. Pen testers use it for the first step, then verify and exploit manually.
  • Firewalls, IPS, or rate limits can block or distort results.

ADVANCED

9. Best practices

  • Get written permission and define the scope first.
  • Update plugins before every scan.
  • Prefer credentialed scans for accurate results.
  • Scan at off-peak hours for production systems.
  • Test your policy on a lab system first.
  • Scan regularly, not just once.
  • Prioritize by risk (VPR, asset importance), not only CVSS.
  • Keep reports safe. They are a map of your weaknesses.
  • Always re-scan after fixing.
